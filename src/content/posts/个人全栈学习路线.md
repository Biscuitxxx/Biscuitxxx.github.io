> 说明：以我自己的私人音视频库项目作为主线，从入门单体逐步往企业架构演进，不盲目上微服务，每个阶段都能做出可运行、可放进简历的成品，同时贴合面试考点。
> 基线起点：Vue3 + SpringBoot + MySQL + MinIO（我最初设想的入门全家桶）

## 阶段 0｜起点：入门原型（学习练手、作品集底座）

**技术栈**：Vue3 + SpringBoot + MySQL + MinIO + Nginx
**核心能力**

- 前端：基础页面、列表、原生 audio/video 播放器、简单上传
- 后端：基础 CRUD、文件上传、MinIO 预签名 URL、元数据入库
- 存储：音视频文件存 MinIO，数据库只存元数据（标题、标签、封面、播放记录）
**约束（适配 J1900 弱主机）**
- 不做服务端转码、不自动 ffmpeg 批量生成缩略图
- 视频播放做好 Range 请求，支持进度拖拽
**产出**：可用私有影音库，能上传、分类、在线播放
**定位**：个人 Demo，适合理解前后端分离、对象存储的基础思想；距离商用系统缺少缓存、权限、异步能力

## 阶段 1｜标准企业单体（小公司主流架构，优先完成）

**技术栈**：Vue3 + SpringBoot + MySQL + Redis + Sa-Token + MinIO + Nginx
**新增内容**

- Redis：登录 Token 缓存、热点列表缓存、浏览计数、验证码
- Sa-Token：完整权限体系（私有资源、分享链接、访客 / 管理员区分）
- Nginx：反向代理、静态资源托管、请求限流
- 功能增强：分页、收藏、播放历史、带时效的分享链接、分块大文件上传
**产出**：一个可以稳定私有化上线的单体影音系统
**定位**：市面上绝大多数中小后台、内部管理系统的标准形态；面试高频技术栈，**优先吃透这个阶段，不急着微服务**

核心认知：微服务不是"更高级"，是业务复杂、团队多人协作、需要单独扩容才会拆，小系统硬上属于过度设计

## 阶段 2｜单体进阶（加入异步、检索，贴近中型业务）

**技术栈**：在阶段 1 基础上增加：RabbitMQ/RocketMQ + Elasticsearch
**新增内容**

- MQ 消息队列：异步任务解耦（缩略图生成、通知、批量标签同步，ffmpeg 任务放到性能更强的机器执行，不占用 J1900）
- Elasticsearch：音视频标题、标签、歌手 / 专辑的全文检索，替代 MySQL 模糊查询
- 可选补充：MySQL 主从、读写分离
**产出**：带异步任务、高速检索的增强版影音库
**定位**：理解异步解耦、搜索引擎的价值；为后面微服务拆分打思想基础

## 阶段 3｜SpringCloud 微服务（中型企业架构，面试重点）

**技术栈**：SpringCloud Alibaba（Nacos + Gateway + Sentinel） + Redis 集群 + MQ + ES + MinIO + MySQL（主从 / 分库分表）
**服务拆分参考（以影音库举例）**

- 用户服务：登录、权限、用户信息
- 元数据服务：音乐、视频、专辑、标签管理
- 文件服务：专门对接 MinIO，上传、预签名、文件校验
- 搜索服务：对接 ES，提供检索接口
**新增能力**
- 注册 & 配置中心、网关统一入口、限流熔断、分布式配置
- 服务独立部署、独立扩容
**代价**：复杂度大幅上升，要处理分布式调用、超时、事务、链路排查
**定位**：中大型业务系统；实习面试 Java 后端重点考察方向，**学习优先级放在单体吃透之后**

## 阶段 4｜大厂分布式云原生架构（海量高并发场景）

**技术栈**：微服务 + K8s + Kafka + ELK + Prometheus + SkyWalking + CDN + 分库分表
**新增内容**

- K8s：容器编排，自动扩缩容、滚动发布
- Kafka：超高吞吐日志、行为埋点、播放统计
- ELK：日志集中收集查询
- SkyWalking：分布式链路追踪
- Prometheus+Grafana：全链路监控告警
- CDN：静态资源、音视频分发加速
- 大数据组件：Flink 做播放行为统计、简单推荐
**定位**：B 站、网易云这类音视频平台会用到；学习门槛高，适合作为长期拓展方向，新手不用优先落地

## 补充两条并行技术支线（可选，按需学习）

1. Go 支线：MinIO 本身是 Go 开发，适合写轻量文件服务、网关、存储相关服务，低 CPU 占用，适合弱设备
2. BFF 支线：Node/Java BFF 层，前端聚合接口，减少前端请求次数

## 学习原则（博客小结，放在末尾）

1. 主线优先：**先把单体吃透，再碰微服务**，不要上来跟风学微服务
2. 项目驱动：所有技术都在这个影音库项目上迭代，而不是零散学教程
3. 硬件适配：J1900 只负责文件分发、元数据接口；转码、重负载任务外放到性能更好的主机
4. 简历导向：阶段 1、阶段 2 的内容，已经足够支撑 Java 全栈实习面试
